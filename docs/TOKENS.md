# Design tokens reference

This document is the **consumer- and agent-facing map** of Magma's design tokens: which families exist, which of them UI code should paint with, and how to consume them. The rules for coloring a UI are in [`agents/color.md`](./agents/color.md) and [`agents/theming.md`](./agents/theming.md) (shipped in the packages); for how tokens are **structured, built, and named at the source**, see [`projects/design-tokens/SPEC.md`](../projects/design-tokens/SPEC.md).

## What tokens are

Magma's design tokens are built with **Style Dictionary** (multi-format output) and color values are derived through **Adobe Leonardo** to guarantee contrast across the scales. The sources live in [`projects/design-tokens/`](../projects/design-tokens):

| Category     | Source                                                                                                                 | Owns                                                                                          |
| ------------ | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `color`      | generated by the design-tokens CLI from `.magma-design-tokensrc.json` (Leonardo), written to `tokens/color/generated/` | tone, status, label, variant and brand ramps; the per-family surface, border and text ladders |
| `typography` | `tokens/typography/`                                                                                                   | font families, sizes, line heights of the semantic type scale                                 |
| `sizing`     | `tokens/sizing/`                                                                                                       | spacing, gap, radius, aspect ratio                                                            |
| `screen`     | `tokens/screen/`                                                                                                       | breakpoints                                                                                   |
| `cosmetic`   | `tokens/cosmetic/`                                                                                                     | border, border radius, box shadow                                                             |
| `css`        | `tokens/css/`                                                                                                          | layout grid, padding and margin sizing, transitions (durations, timing functions)             |

Tokens are exposed to consumers in multiple formats (CSS custom properties, Tailwind utilities, SCSS variables, hex CSS files, JSON for design tools). The exposure surface is owned by [`projects/styles/SPEC.md`](../projects/styles/SPEC.md).

## Two levels of color

- **Semantic roles** (`--magma-*`, generated into `styles/dist/css/semantic.css`): what UI code paints with. A role says what the element is (the page, a card, secondary text, the primary action, a danger state) and resolves per mode, per named theme and per contrast preference. The full list and the pairing rules: [`agents/color.md`](./agents/color.md).
- **Primitive ramps** (design-tokens): the palette the roles are built from. A primitive follows only the light / dark mode: it stays grey under a tinted theme and gains no contrast under `pref-contrast-more`.

So the first answer to "which colour do I use for X?" is a role, not a family.

## Color families - what each one is for

| Family                                                       | What it is                                                                                                                            | In UI code                                                                                                  |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `tone-neutral-*`                                             | the neutral ramp                                                                                                                      | behind the neutral roles (`surface-*`, `wash-*`, `text-*`, `border-*`): paint with the roles                |
| `tone-porcelain-*`, `tone-bisque-*`                          | cool and warm neutral ramps                                                                                                           | behind the named themes `cool` and `warm`: switch them on with `data-theme-name`, do not paint them by hand |
| `tone-kaolin-*`, `tone-fireclay-*`                           | further neutral ramps                                                                                                                 | no role and no theme use them today                                                                         |
| `status-info-*`, `-success-*`, `-warning-*`, `-error-*`      | the status ramps                                                                                                                      | behind the status roles `--magma-<hue>-*` (`error` is the `danger` hue)                                     |
| `variant-primary-*`, `variant-ai-*`                          | the accent ramps (aliases of `brand-maggioli` and `label-violet`)                                                                     | behind `--magma-accent-*` and `--magma-accent-ai-*`                                                         |
| `variant-secondary-*`                                        | a legacy ramp                                                                                                                         | no role; `variant="secondary"` on a component renders like `primary`                                        |
| `label-*`                                                    | twelve categorical hues (`red`, `amaranth`, `aqua`, `blue`, `green`, `lime`, `orange`, `orchid`, `purple`, `sky`, `violet`, `yellow`) | legitimate directly, when the colour encodes data: a category, a tag, a colour the user picked              |
| `brand-*`                                                    | Maggioli brand palettes                                                                                                               | legitimate directly, for brand identity (logo containers, brand panels)                                     |
| `surface-<family>-*`, `border-<family>-*`, `text-<family>-*` | per-family ladders (`neutral`, `porcelain`, `bisque` and the statuses)                                                                | the primitives behind the roles: paint with `--magma-surface-*`, `--magma-border-*`, `--magma-text-*`       |

### Decision tree

When unsure which colour to use:

1. Is it part of the interface (page, card, text, border, action, state)? -> a semantic role, see [`agents/color.md`](./agents/color.md).
2. Does the colour **encode data** (a category, a tag, a user-chosen colour)? -> `label-*`.
3. Is it a **brand identity** surface? -> `brand-*`.
4. Otherwise there is no primitive to pick: name the role.

## Levels - the numeric suffix

Every ramp has a numeric ladder (`-01` ... `-10`) plus `-seed`. This is a **contrast ladder**, not a fixed lightness - Leonardo generates each step to maintain a defined contrast ratio against the background. The same `-03` token lands at a different absolute lightness in light vs dark mode.

```css
/* tone-porcelain ladder in light mode */
--tone-porcelain-01: 4 5 6; /* highest contrast */
--tone-porcelain-03: 61 73 91; /* secondary text level */
--tone-porcelain-08: 201 208 219; /* low contrast - fills, borders */
```

**Rule of thumb**: low numbers are high contrast, high numbers are low contrast; `-seed` is the pure extreme of the mode (`#fff` light, `#000` dark), not a surface. The roles pick the steps for you: the neutral text default sits on `-01`, the muted text on `-03`. The exact range per family is documented in [`projects/design-tokens/SPEC.md`](../projects/design-tokens/SPEC.md).

## How to consume tokens

| Surface                     | Syntax                                                                   | When to use                                                                                                        |
| --------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| **Tailwind role utility**   | `bg-surface-raised`, `text-fg-muted`, `border-border-default`            | **Default** in app code (needs `styles/dist/tailwind/theme.css`, see [`agents/assets.md`](./agents/assets.md))     |
| **CSS role var**            | `rgb(var(--magma-surface-raised))`, `rgb(var(--magma-text-muted) / 0.5)` | Plain CSS, component CSS vars, alpha                                                                               |
| **Primitive utility / var** | `bg-label-sky-09`, `rgb(var(--label-orchid-04))`                         | Only for colours that encode data or brand identity                                                                |
| **SCSS variables**          | `$color-tone-neutral-light-3` (hex, one variable per mode)               | Legacy SCSS consumers only: no dark flip, no theme                                                                 |
| **JS**                      | `@maggioli-design-system/design-tokens` exports `{ palette }`            | The Tailwind 3 colour functions behind the JS preset; Tailwind 3 only                                              |
| **JSON**                    | `@maggioli-design-system/design-tokens/dist/json/`                       | Design tools (Figma tokens)                                                                                        |
| **Hex CSS files**           | `colors-hex-*.css` imports                                               | Only when the consumer cannot evaluate the `rgb(var(--...))` wrapper - never in Tailwind or web component contexts |

### Why RGB and not hex by default

The CSS custom properties hold **space-separated RGB components**, not full colour values:

```css
:root {
  --tone-neutral-03: 73 73 73; /* not #494949, not rgb(73,73,73) */
}
```

This lets you compose alpha at the call site:

```css
.foo {
  background: rgb(var(--magma-accent-emphasis) / 0.15); /* tint */
  color: rgb(var(--magma-text-muted)); /* solid */
}
```

The hex variants (`colors-hex-*.css`) are pre-rendered for consumers that can't do the `rgb(var(--...))` evaluation. Don't import them in Tailwind- or web-component-based apps.

## Dark mode, themes and contrast

Token values flip at the **palette level** - you don't write conditional colour code. Activate the mode with a class on `<html>`:

```html
<!-- one of: pref-mode-system (follows the OS), pref-mode-light, pref-mode-dark -->
<html class="pref-mode-system"></html>
```

Because the same token name resolves to different values in each mode, code authored against tokens works in both automatically. **Do not write `@media (prefers-color-scheme: dark)` queries or per-mode overrides.** The same activation pattern applies to the other preferences (`pref-contrast-*`, `pref-animation-*`, `pref-consumption-*`), and a named theme is one attribute (`data-theme-name="cool"`). Only the roles follow the themes and the contrast preference: [`agents/theming.md`](./agents/theming.md).

## Non-colour tokens

- **Typography** - consume via the semantic utilities (`text-title-h1`, `text-info-paragraph`, `text-code-snippet`) or their plain-CSS `typography-*` classes: [`agents/typography.md`](./agents/typography.md). **Never** compose `font-*` and `text-*` primitives by hand.
- **Sizing** - use Tailwind spacing utilities (`p-4`, `gap-2`, ...), which map to `--spacing`. For radii use the `--magma-radius-*` scale, which follows the corner geometry ([`agents/theming.md`](./agents/theming.md)).
- **Screen** - use the Magma breakpoint prefixes (`mobile:` 480px, `tablet:` 768px, `desktop:` 1024px, `wide:` 1280px, `large:` 1440px, `xlarge:` 1600px, `tv:` 1920px; `max-*` for the upper bound), which map to the screen tokens.
- **Cosmetic** - shadows (`--shadow-md-sharp`, `--shadow-2xl`, ...), borders, radii. The CSS variables come from `styles/dist/css/typography.css` ([`agents/assets.md`](./agents/assets.md)). Opacities such as `--magma-disabled-opacity` are not tokens: they are global design decisions of `styles` ([`agents/theming.md`](./agents/theming.md)).

## Anti-patterns

- Raw Tailwind colour primitives (`bg-white`, `bg-gray-500`, `text-red-700`) - use the role utilities (`bg-surface-default`, `text-fg-muted`)
- Painting the interface with a primitive ramp (`bg-tone-neutral-09`, `text-status-error-03`) - it ignores the named theme and the contrast preference; use the role
- Literal `rgba(...)` values - use the `rgb(var(--...) / alpha)` wrapper
- Hard-coded hex codes in component styles - token-only
- Importing `colors-hex-*.css` in Tailwind / web-component projects - only the RGB format works with the system
- Manual dark-mode media queries - the palette flips for you
- Picking a `label-*` colour for status communication - use the status roles
- Painting everything with the accent - its weight is for calls to action and the most important affordances
